# CaseShelf（社内事例写真アプリ）第1段階 試作品

社内の案件写真を投稿・検索・閲覧するWebアプリの「操作できる試作品」です。
利用者（ログインアカウント）は架空ですが、サンプル投稿14件の**案件名・クライアント名・
ハッシュタグ・写真**は、昭栄美術の公開実績ページ（https://www.shoei-bijutsu.co.jp/works/）
に掲載されている情報・画像をそのまま使用しています。**実際の社内写真や、まだ公開されていない
案件・顧客の情報はこの試作品に投入していません。**

サンプル投稿（案件名が「seed_」で始まるID）は、このアプリを開くたびに最新の内容に自動更新
されます。コード側のサンプルデータを変更して公開し直せば、以前そのブラウザでこのアプリを
開いたことがある人にも新しい内容が反映されます。一方、利用者が実際に投稿・編集した案件は
この自動更新の対象外で、そのまま保持されます。

## 1. 動かし方

このアプリは**ビルド不要**です（Node.js／npmがこの開発機に入っていなかったため、第1段階はReact
をCDNから読み込む構成にしています。詳しくは「6. 技術構成と制約」参照）。

```bash
cd <このREADMEがあるフォルダ>
python3 -m http.server 8787
```

ブラウザで `http://localhost:8787` を開いてください。Python以外でも、`index.html` を静的配信できる
サーバーであれば何でも動きます（VS Codeの Live Server 拡張、`npx serve` など）。

- データはブラウザの **localStorage** に保存されます（この端末・このブラウザだけ）。他の人や他の端末とは
  共有されません。本番相当の共有データベースは第2段階の対象です。
- 検索条件・スクロール位置の保持には **sessionStorage** を使っています（タブを閉じると消えます）。
- 一度操作してデータを試作的に変更した後、まっさらな状態に戻したい場合はブラウザの開発者ツールで
  `localStorage.clear()` を実行するか、サイトデータを削除してください。

## 2. ログイン（試作品）

ログイン画面には架空の利用者が一覧表示され、クリックするだけでそのアカウントとしてログインできます。
**実際のパスワード認証・本番相当のアクセス制御は行っていません。** 本番では管理者による招待とメール認証
によるログインを予定しています（開発指示書 4章）。

試せるアカウント：
- 佐藤 management（管理者） — 管理者画面にアクセスできます
- 山田 花子 / 田中 次郎 — 一般利用者（それぞれ自分の投稿のみ編集・削除可）
- 停止 三郎（利用停止サンプル） — クリックしてもログインできません。管理者が利用停止にした利用者が
  写真・案件情報にアクセスできなくなる挙動のサンプルです。ログイン中に管理者画面から自分以外の利用者を
  停止にした場合も、次の操作時に強制的にログアウトされます。

## 3. 実装済みの機能（第1段階）

- 写真グリッド一覧（新着順）、スマートフォン3列／PCは画面幅に応じて4〜6列
- 複数写真案件へのバッジ表示、スクロールに応じた読み込み（無限スクロール風）
- 案件名・ハッシュタグ検索（`#`の有無を問わない）、検索条件の表示・解除
- タグをクリックしてそのタグで絞り込み
- 一覧に戻った際の検索条件・スクロール位置の保持（検索条件ごとに保持）
- 案件詳細（写真を大きく表示、スマホはスワイプ・PCは矢印、現在の写真番号/総枚数）
- タグから一覧へ遷移、Salesforce案件URLがある場合のみ「Salesforceで案件を見る」ボタン表示
  （実際の自動連携は行わず、登録されたURLを新しいタブで開くだけです）
- 案件の新規投稿・編集（複数写真アップロード、並べ替え、代表写真の変更、削除）
- アップロード状況の表示（擬似プログレスバー）とエラー表示（非対応形式・サイズ超過・枚数超過）
- 投稿者本人（または管理者）のみ編集・削除可。削除は確認ダイアログを表示
- 保存（ブックマーク）、保存の解除、保存一覧画面（利用者ごとに非公開）
- プロフィール画面（表示名・プロフィール画像の変更、自分の投稿一覧）
- 管理者画面（利用者の招待・停止／復帰、投稿とタグの管理・削除）
- 一般利用者は管理者画面にアクセスできない（アクセスするとURLを直接叩いても一覧へリダイレクト）
- 対象外機能（いいね・コメント・通知・DM・フォロー・ストーリーズ・リール・動画投稿・外部公開等）は
  画面上に一切表示していません

## 4. 試作品としての割り切り・未実装事項

開発指示書 8章・9章に基づき、以下は意図的な割り切りです。実際の運用には第2段階での対応が必要です。

| 項目 | 試作品での扱い |
|---|---|
| ログイン・認証 | 実際の認証なし。利用者一覧から選ぶだけ（4章参照） |
| データ保存先 | この端末のブラウザのlocalStorageのみ。複数人・複数端末での共有なし |
| 写真の保存 | アップロードした画像はBase64形式でlocalStorageに保存（軽量画像への変換・CDN配信は未実装） |
| アップロード進捗 | 実際のサーバー通信はないため、進捗バーは疑似的な表示です |
| 利用者招待 | 実際のメール送信は行いません（画面上の操作のみ） |
| Salesforce連携 | 自動同期は範囲外。登録したURLを開くだけ（開発指示書の指定通り） |
| バックアップ・復元 | 未実装（第2段階の対象） |

### 写真の枚数・容量・対応形式の上限（提案・要確認）

開発指示書8章の指示に基づき、実装前の提案として以下の上限を試作品に仮実装しています。本番仕様として
確定する際はご確認ください。

- 1案件あたり最大 **20枚**
- 1枚あたり最大 **5MB**
- 対応形式: JPEG / PNG / WEBP / GIF

## 5. 未検証・今後確認が必要な事項

- 実際のスマートフォン実機・各種ブラウザでの表示崩れの確認（このセッションではPC上のブラウザでの
  表示確認のみ行いました）
- 大量の案件・大量の利用者を投入した際の表示速度（localStorageの容量上限にも注意が必要です。目安として
  ブラウザ全体で5〜10MB程度が上限のことが多く、写真を多く登録すると上限に達する可能性があります）
- 第2段階で本番のデータベース・認証基盤に置き換える際のデータ移行方法

## 6. 技術構成と制約

この開発機には **Node.js／npmがインストールされていません**でした。そのため第1段階の試作品は、
ビルドツール（Vite/Webpack等）を使わず、ブラウザから直接動かせる構成にしています。

- React 18 / ReactDOM 18 / Babel Standalone を CDN から読み込み
- 画面はReact（`React.createElement`）で実装、ルーティングは `location.hash` を使った自作の簡易ルーター
- スタイルは素のCSS（`styles.css`）
- サンプル投稿14件の写真は、昭栄美術の公開実績ページ（shoei-bijutsu.co.jp/works/）に掲載されている
  画像を直接参照（ホットリンク）している。新規投稿・編集でアップロードした写真は、引き続き
  Base64形式でlocalStorageに保存される（placeholderPhoto関数は現在未使用だが、`AppData`からは
  参照可能なまま残している）

**第2段階（本番機能）に進む際は、Node.jsのインストールを前提に、Next.js等のフレームワーク＋実際の
データベース（例: PostgreSQL等）・認証基盤・オブジェクトストレージへの置き換えを想定しています。**
外部サービスの契約・有料サービスの利用・公開前には、構成と費用を別途ご提示します。

